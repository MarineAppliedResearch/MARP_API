# The MARP developer documentation template

`/developer-docs` is generated by jsdoc. This is the template it is generated
with: a fork of [docdash](https://github.com/clenemt/docdash) **2.0.2**, changed
only where MARP's identity differs from docdash's default, which is a light grey
page in Source Sans Pro with a teal sidebar.

Forked in `MARP_API#140`, which asked for the generated documentation to look
like the rest of the platform rather than like a template nobody chose.

## Why a fork rather than an extra stylesheet

docdash has a supported seam for this — `docdash.scripts` in `jsdoc.config.json`
takes a list, and an entry ending in `.css` becomes a `<link>`. It was the first
approach, and it was rejected for two reasons. The link is emitted at the **end
of `<body>`**, so every page paints the default theme before repainting in
MARP's; and there is nowhere in the layout to put a header, so a page reached
from a deep link never says what product it belongs to.

The cost is that this directory drifts from upstream. That is what the next
section is for.

## What was changed, and where

Everything else is byte-identical to docdash 2.0.2, so `diff -r` against
`node_modules/docdash` is the upgrade procedure.

| Path | Change |
| --- | --- |
| `publish.js` | One line, re-exporting docdash's. No logic is forked. |
| `tmpl/layout.tmpl` | The MARP header bar, the stylesheet link in `<head>`, a favicon, and a footer that names MARP. |
| `static/styles/marp-docs.css` | New. Every MARP rule on the site is in this one file. |
| `static/styles/jsdoc.css` | Four `@font-face` blocks removed from the end. |
| `static/fonts/` | Not copied. |
| the other 17 `tmpl/` files | unchanged |
| `static/scripts/` | unchanged |

The fonts went because MARP's type is a system stack — `--body-font` and
`--display-font` in `tokens.css` name no webfont — so Montserrat and Source Sans
Pro were 1.2 MB of files nothing would ever render. Removing the files without
removing the `@font-face` blocks would leave four rules pointing at nothing,
which is why both halves are listed.

## The palette is copied, and a test says so

`marp-docs.css` opens with a `:root` block holding the MARP colours. They are
**copied** from `frontend/shared/assets/css/tokens.css` rather than linked,
because this site is built as files and has to work opened from disk, with no
server to resolve `/assets/...` against.

A copy drifts silently, so it is checked rather than trusted:
`tests/docs-branding.test.js` reads both files and fails when a value here stops
matching the one in `tokens.css`. That is also why there is no hex anywhere else
in the stylesheet — a colour typed into a rule is invisible to that check.

## Building it

```bash
npm run docs:build
```

`docs/developer/` is committed, so the build is part of a change rather than
something run afterwards. `scripts/copy-doc-assets.js` runs at the end of it and
copies the images the front page needs; `README.md` is the front page, and its
image paths are relative to the repository root.
